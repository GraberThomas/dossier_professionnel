\begin{frame}{C3.1 + C3.2 — Une pipeline simple, mais réellement reproductible}
\context{B3}{C3.1 · C3.2 · piv2glz}
\begin{columns}[T]
\begin{column}{0.44\linewidth}
\begin{tightitems}
  \item GitLab CI démarre dans un environnement Python propre.
  \item Les tests Pytest couvrent fonctions, erreurs et scénarios CLI de bout en bout.
  \item Le stage \texttt{build} n'est exécuté que si le stage \texttt{test} réussit.
  \item PyInstaller produit un exécutable autonome et une distribution \textit{onedir} compressée.
  \item Les artefacts sont récupérables directement depuis la pipeline.
\end{tightitems}
\vspace{0.25em}\small\strong{Effet :} une modification n'est plus validée par quelques conversions manuelles avant livraison.

\begin{frame}{Un incident révélateur : le champ PDF /UserUnit}
\context{B3}{C3.3 · Diagnostic post-production}
\begin{block}{Symptôme}
Certains PDF générés étaient interprétés avec des dimensions plusieurs fois supérieures à la taille attendue malgré une conversion à 300 DPI apparemment correcte.
\end{block}
\begin{columns}[T]
\begin{column}{0.47\linewidth}
\begin{tightitems}
  \item Inspection du PDF : présence d'un \texttt{/UserUnit} proche de 300/72.
  \item Lecture de l'ancien code Eiffel : il neutralisait explicitement cette valeur.
  \item Cette règle n'était documentée nulle part ailleurs.
\end{tightitems}
\end{column}
\begin{column}{0.49\linewidth}
\begin{block}{Correctif et leçon}
J'ai ajouté un correctif Python après la conversion.\\[0.4em]
\textbf{Une migration legacy ne consiste pas seulement à reproduire la fonction principale : elle doit retrouver les années de règles implicites accumulées.}
\end{block}
\end{column}
\end{columns}
\end{frame}

\begin{frame}{C3.4 — Moving from manual Helm releases to GitOps}
\selectlanguage{english}
\context{B3 · ENGLISH}{C3.4 · Homelab}
\begin{columns}[T]
\begin{column}{0.44\linewidth}
\begin{tightitems}
  \item My homelab is a personal experimentation environment, not a professional production system.
  \item I initially deployed Kubernetes workloads manually with Helm.
  \item I then introduced Argo CD so that Git becomes the source of truth for the desired state.
  \item A change committed to the repository can be detected and reconciled automatically by Argo CD.
\end{tightitems}
\vspace{0.2em}\small\strong{Main benefit:} deployment becomes a \textbf{repeatable state reconciliation process} instead of manual commands.
\end{column}

\begin{frame}{C3.5 — Observability closes the deployment loop}
\context{B3 · ENGLISH}{C3.5 · Homelab}
\begin{columns}[T]
\begin{column}{0.45\linewidth}
\begin{tightitems}
  \item Prometheus collects metrics.
  \item Grafana provides dashboards and visualization.
  \item Loki stores logs and Alloy collects them from services.
  \item Kubernetes and Argo CD expose deployment and health information.
  \item The objective is not only to deploy faster, but to \textbf{understand the effect of a change after deployment}.
\end{tightitems}
\end{column}
\begin{column}{0.51\linewidth}
\centering
\repofigure[0.49\textheight]{figures/homelab/fig_8_1_architecture_homelab.png}
\end{column}
\end{columns}
\begin{block}{Limit}
The environment is intentionally small and personal. It strengthens my understanding of modern DevOps practices, but it does not replace the professional evidence provided by Ediacara.
\end{block}
